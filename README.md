# rtl-viewer

FPGA/ASIC 源码工程查看器：打开源码文件夹（或把文件夹直接拖进窗口），自动识别 Verilog/SystemVerilog/VHDL 源码与 Vivado IP 核（`.xci`）。顶部提供工程与文件操作，左侧为工程层级与当前文件大纲，中间为 Monaco 编辑器，下方可打开信号链分析；支持原有深浅主题切换。

## 功能

- **层级树**：从顶层模块按例化关系逐层展开；多顶层时自动识别（仿真环境向内解包出真实顶层），树上方下拉可切换；点击节点打开模块定义，节点行的 ↩ 图标或右键菜单「跳到例化点」跳到父模块中的例化点（右键另含「查看例化处」——列出工程内例化该模块的所有位置并点击跳转，以及复制模块名/文件名/路径/所在目录、在资源管理器中显示，未使用与约束分组同样支持）；IP 核显示为黑盒节点（点击跳到例化点）；无父无子的孤儿模块（未被例化、也不例化任何模块的定义）归入「未使用」分组；循环例化标注不展开。
- **紧凑层级与键盘导航**：顶层模块标签与下拉选择同一行显示，长名称保留完整悬停提示。模块树每行 28 px，按 `实例名 : 模块名 (定义文件名)` 单行显示，顶层与未使用模块显示 `模块名 (定义文件名)`，IP 显示对应 `.xci` 文件名；无定义文件的节点仅显示实例与模块名。悬停查看完整名称、类型与路径；跳到例化点按钮在悬停或键盘聚焦时显示。方向键上下移动、左右展开或收起，Home/End 到首尾，Enter/空格打开定义，Tab 可进入例化点按钮。大量模块在层级区内部滚动，深层名称随键盘焦点滚入视口，不挤走大纲。侧栏可拖动调整宽度（160～600 px），重启恢复上次宽度。
- **节点类型图标**：普通模块保留方形模块图标，IP 核为紫色菱形；BUFG、DCM 等已识别厂商原语使用青绿色侧边引脚芯片图标和正常文字，未解析模块使用灰色问号。悬停及辅助读屏均提供类型与定义名。
- **全局搜索**：顶部「搜索」或 Ctrl+Shift+F 展开编辑区下方的独立搜索面板，可与工程层级、文件大纲及信号链同时显示；拖动上边缘或聚焦分隔条后按上下方向键调整高度。再点「搜索」、面板关闭按钮或输入框内 Esc 收起并保留查询与结果。搜索包含当前工程已打开文件的未保存内容，按文件分组展示、命中高亮，点击结果精确定位并选中命中内容；源码变化后提示刷新结果；Aa 切换大小写敏感、「词」整词匹配、「.*」正则表达式（无效正则有提示）；编辑器里 Shift+F12 或右键「查找引用」对选中/光标下的标识符做字面整词全局搜索，不继承手工正则选项；Verilog 区分大小写，VHDL 不区分大小写。
- **当前文件大纲**：侧栏下方列出当前文件的模块/信号/进程/例化，always/process 块带赋值目标（一眼区分块用途），顶部过滤框键入即筛，点击跳行；面板高度可拖拽调整、可折叠（状态记忆），「⊙」按钮弹出可模糊过滤的符号列表（同 Ctrl+Shift+O），回车跳转；光标移动时状态栏显示面包屑「模块 › 进程」，大纲对应条目同步高亮。
- **导航历史**：跳转前自动记录位置，Alt+←/→ 或编辑器面包屑栏按钮前进后退；左右编辑区各自维护历史，返回时恢复行、列与单行选区，不把另一侧的阅读路径带过来。
- **信号链入口**：在源码信号上右键选择「追踪此信号」，在编辑区下方用统一的横向卡片和箭头显示结果；当前信号带明确标记、强调边框和背景，名称旁的图标定位源码，当前信号返回发起追踪的代码行，跨层端口定位对应的端口映射行。移动光标、选择文本、浏览文件和树实例均不改变目标；顶部「信号链」按钮只显示／收起面板，尚无目标时提示右键追踪。按实例路径区分复用模块，源码图标只定位代码；收起、重开及进入子模块后返回保留阅读状态。当前缓冲区快照按需分析与缓存，修改源码后保留旧图并提示刷新，点击刷新才重新分析原目标。底部高度支持拖动和键盘调整。
- **端口连接**：`input`／`output`／`inout`（包括 `output reg`）以当前信号卡片为中心，左侧来源、右侧去向；赋值终点明确区分「驱动赋值」和「读取赋值」，代码中的当前信号高亮显示。顶层输入／输出／双向的外部边界直接标在端口卡片内，不重复绘制同名节点。跨层卡片将实例路径和端口方向／名称分行显示，父模块内部信号另行标明；赋值终点保留所属实例，不合并不同实例的同一条源码赋值。切片或运算端口映射保留绑定语法，与赋值区分。沿实例端口连接追到赋值位置或顶层接口；单路连接直接延伸；连接扇出先列出各直接去向，点击卡片或「继续追踪」才接出该路后续，可同时追踪多路，再次点击可收起该路后续；其他路线及仍被使用的汇合节点保留，未展开路线不提前绘制后续连线。赋值终点可进入所在模块的内部逻辑。
- **模块内逻辑**：内部 `reg`／`wire`／`signal` 以横向路径显示相关来源、运算和后续使用，边界为本模块端口与子模块端口；子模块通过「进入子模块」另行查看，不推测其输入到输出关系。条件保留 `if`／`elsif`／`else`／`case`／`when` 代码形式，每层列出直接分支，嵌套层级按选择向右接出，不堆叠成长卡片。赋值只显示一次，各分支图标定位对应代码行。再次点击分支可收起其后续，保留前缀与下级选择，重开后恢复；支持多支同时查看、全部展开和全部收起，共享后续只显示一次。寄存器卡片标注更新逻辑与时钟，当前状态卡片标注「当前值 Q」并以虚线连接；连线接点固定在卡片上部，同一行水平连接，不随代码展开／收起移动；多条输入／输出使用独立接点，跨列长线从卡片外侧绕行，避免箭头挤在同一入口或穿过中间卡片。运算符保留实际赋值类型，不根据时钟推断；VHDL 分支保留 `rising_edge`／`falling_edge` 保护条件，不把时钟分支改写成无条件 `else`。子模块端口同样按实例与端口分行，停止原因直接显示在卡片内；未知方向用无箭头虚线表示，不计作已确认驱动。
- **编辑器**：Monaco（VS Code 内核），Verilog/SV/VHDL 语法高亮；多标签页（右键：关闭/关闭其他/关闭右侧、复制文件名/路径/所在目录、在资源管理器中显示）、未保存 `*` 标记、保存（Ctrl+S）/另存为/新建、查找替换、Ctrl+Click 跳转模块定义、Ctrl+/ 切换行注释、Alt+Z 切换自动换行（编辑器右键菜单也有入口）、Ctrl+滚轮缩放字号。
- **新建 HDL 文件**：点击「新建 .v」或 Ctrl+N 直接创建文件，右侧下拉选择 `.v`、`.sv`、`.vhd` 时立即新建并记住类型，重启后继续使用；打开其他类型的文件不会改变偏好。空白标签在保存前即可使用对应语言的高亮、补全和注释。首次保存默认带上后缀，目录优先沿用当前文件所在目录，其次为工程根目录。
- **路径与菜单**：编辑区路径中的目录可点击打开对应文件夹，文件名可点击在资源管理器中定位。路径过长时将祖先目录收进「…」，保留父目录与文件名，悬停查看完整路径。两侧打开不同路径的同名文件时，标签追加最短可区分目录，如 `top.v (rx)`／`top.v (tx)`；同一路径的两个视图不重复区分，关闭或另存为后自动更新名称。标签悬停始终保留完整路径，外部修改警告附在路径之后。切换标签时活动标签自动滚入视口；新建类型、最近工程、编码及应用右键菜单支持方向键、Home/End、Enter/空格和 Esc，关闭后恢复焦点。
- **列编辑**：Alt+左键拖动或 Alt+Shift+方向键建立矩形选区，可直接输入、删除和粘贴；Alt+Shift+PageUp/PageDown 按页扩展。编辑器右键也可切换矩形选择模式。按 Alt+C、顶部「列编辑」或编辑器右键「列编辑…」批量插入文本或数字，支持初始值、增量、重复次数、十／十六／八／二进制、前导零／空格及十六进制大小写，显示作用范围与结果预览。数字输入框按所选进制解释，空增量为 0、空重复次数为 1。矩形／多光标按从上到下的实际选区替换；仅有单光标时从当前列处理到文件末尾，短行补空格，Tab 内插入保持后方对齐。一次撤销恢复整批操作；本次运行期间记住上次成功使用的设置。
- **代码补全**：输入即提示（Ctrl+Space 手动触发）当前文件信号、端口、参数与例化名、全工程模块名、语言关键字和常用块 snippet。独立例化位置选中模块名时，Verilog 生成 `#(...)` 参数与端口骨架，VHDL 生成 `entity`、`generic map` 与 `port map`，保留已输入的标签和库名；Tab 逐项编辑占位符。未写完的例化中，连接左侧提示尚未填写的端口／参数名，右侧提示当前文件信号；参数默认值与同名连接是可修改模板，需按目标工程检查类型、宽度和表达式。
- **分屏双视图**：顶部「分屏」、Ctrl+Alt+V、编辑器右键「在另一侧视图打开」或标签右键「向右拆分视图」把编辑器分成左右两组，两组各看各的文件；F8 在已显示的左右视图间切换焦点。同一文件在两侧共享缓冲区和未保存状态，编辑实时互通。进入分屏时收起信号链，为两侧编辑区留出空间，也可手动重新展开；两组间的分隔条可拖拽调宽。顶部「分屏」或第二组收起按钮仅隐藏右侧，保留标签、未保存内容、阅读位置和分栏宽度，再打开恢复。关闭文件使用标签上的关闭按钮或 Ctrl+W。
- **约束文件查看**：`.xdc`/`.sdc` 以「约束」分组展示在树中，使用 Tcl 语法高亮（IP 生成目录的约束不进索引）。
- **外部变更监视**：文件在磁盘被外部修改时，干净标签自动重载、未保存标签标 ⚠；保存时若磁盘已变，弹出「覆盖 / 放弃重载 / 取消」三选，防误覆盖 Vivado 重新生成的内容。
- **最近工程**：工具栏 ▾ 下拉或 Ctrl+Alt+R 列出最近打开的 8 个工程，一键切换。
- **编码自适应**：自动识别 UTF-8/UTF-8 BOM/UTF-16/GBK，默认按原编码写回；状态栏可「以指定编码重新打开 / 以指定编码保存」（Notepad++ 语义），支持 UTF-8、UTF-8 BOM、UTF-16 LE/BE、GBK、GB18030、Big5、Shift-JIS、EUC-KR、Windows-1252，兼容 Vivado 默认 ANSI（GBK）工程。损坏编码与 UTF-32 拒绝读取，单文件读取上限为 64 MiB。
- **快速轻量**：结构扫描只提取模块与例化边，端口按需解析；IP 生成目录不进索引；Windows 单 exe 便携运行，免安装。
- **关闭与工程切换**：关闭脏文件、批量关闭、切换工程和退出提供「保存并关闭／不保存／取消」，默认取消；保存失败或另存为取消时停止操作，全部确认和保存成功后才关闭标签。两侧共享文件只确认一次，单独关闭一个视图而另一视图仍打开时保留缓冲区。磁盘文件被删除时，保存前明确确认是否重建；无法确认磁盘状态时停止保存。保存期间新增编辑仍保留未保存标记。
- **应用标题栏**：品牌栏承担窗口拖动与双击最大化，右上角提供最小化、最大化／还原和关闭。关闭按钮与系统关闭请求共用未保存检查；浏览器预览不显示桌面窗口按钮。

## 信号链分析边界

正常终点显示「无后续引用」或「无赋值来源」；条件与时钟用途也计入引用，`KEEP` 等属性不算逻辑读取。遇到不支持的引用语句、缺失定义或绑定不明时，显示具体分析限制。当前信号的终点状态直接放在当前卡片内。

端口追踪将同一进程内、同一目标的条件赋值合为一张代码卡片和一条连接，保留 `if`／`elsif`／`case` 条件及赋值顺序；不同进程、连续赋值和不同实例分别显示。点击过程标题可收起代码，各赋值行的定位图标跳到原文；支持全部展开、全部收起及返回后恢复状态。不支持摘录的过程保留原始过程源码。

VHDL 过程内的局部变量按过程作用域区分，同名局部变量不会与其他过程或模块端口串链；从源码直接选择时使用光标位置确定作用域。`elsif`／`else` 标注包含此前分支未命中的条件。过程内声明的函数和子程序不会混入外层赋值，调用仍按断点处理；过程边界无法确定时显示停止原因。

这是源码层面的静态分析，不执行综合、仿真或完整 HDL elaboration。端口连接在赋值位置停止；模块内逻辑对支持的 Verilog `always`／VHDL `process` 按语句顺序生成更新规则，区分阻塞／非阻塞及变量／信号赋值，保留条件覆盖、赋值转换和当前状态引用。分支展开是阅读操作，不表示条件实际成立，也没有仿真值或周期时间轴。过程局部变量仍使用按作用域隔离的赋值追踪，可能列出同一过程的多个候选赋值。

常见表达式、三目选择、并发 `when/else`、字符常量聚合（如 `(others => '0')`）、静态位选／切片及精确 `case` 可展示；声明类型与位宽按原文保留，不计算完整位宽／符号传播、重载、四态值或驱动强度。模块内逻辑遇部分目标写入、循环、函数／任务／过程调用、动态下标、未知结构或无法区分的 VHDL 位选／调用时显示边界；黑盒、未知方向及 `generate` 不猜测。模块内逻辑按发起追踪的文件和所在 `architecture` 分析，同名副本不混合；跨层未确定同名 `module` 或多个 `architecture` 的绑定时停止，不显示混合的候选驱动。未发现可继续解析的连接不代表信号未使用。循环检测、节点和表达式展开预算会明确提示截止；未在当前顶层找到实例时仅分析当前模块。

## 构建与运行

当前交付目标为 Windows x64。需要 Node 24、PowerShell 7、Rust MSVC 工具链（版本由 `rust-toolchain.toml` 固定）、Visual Studio／Build Tools 的“使用 C++ 的桌面开发”组件及 Windows SDK，以及 WebView2 Runtime。安装说明见 [Tauri 官方 Windows 前置条件](https://v2.tauri.app/start/prerequisites/#windows)。

### 安装与开发

在项目根目录执行：

```powershell
npm ci
npm run build
npm test
. ./scripts/Initialize-BuildEnvironment.ps1
npm run tauri dev
```

`npm ci` 按锁文件安装；`npm run build` 执行 TypeScript 检查和前端构建。环境脚本只初始化当前 PowerShell 进程，开发与打包均使用项目内 npm 版 Tauri CLI。

脚本优先复用 PATH 中的 Cargo，未找到时从 `CARGO_HOME/bin` 或用户默认 `.cargo/bin` 查找；保留已有 `CARGO_HOME`、`RUSTUP_HOME`。MSVC 使用当前开发终端环境，或通过 vswhere 自动发现。自定义安装位置可在当前终端指定：

```powershell
$env:CARGO_HOME = '<cargo-directory>'
$env:RUSTUP_HOME = '<rustup-directory>'
$env:RTL_VIEWER_VSDEVSHELL = '<visual-studio-directory>/Common7/Tools/Launch-VsDevShell.ps1'
```

只设置实际需要覆盖的变量，不修改系统配置。已有 Developer PowerShell 可不设置 `RTL_VIEWER_VSDEVSHELL`。

### 打包与后端测试

打包入口使用项目内 Tauri CLI，无需全局安装 CLI：

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File scripts/Invoke-Cargo.ps1 test --locked --manifest-path src-tauri/Cargo.toml
pwsh -NoProfile -ExecutionPolicy Bypass -File scripts/Build-Release.ps1
```

唯一交付入口为 `release/rtl-viewer.exe`，双击运行；脚本构建后读取 Cargo 输出目录并复制到此处。若目标被运行中的窗口占用，脚本会报告交付失败；保存工作并退出该窗口后重新运行。不要用裸 `cargo build` 生成分发文件，它不经过 Tauri 的前端打包流程。

### 验收数据与浏览器预览

`npm test` 默认运行单元测试及 `tests/samples/basic/` 中随仓库提供的独立样例，覆盖 Verilog／VHDL 混合层级、IP 黑盒、约束文件和寄存器来源。样例用于查看器验收，不是可综合工程，其中 `.xci` 是手工编写的最小解析输入。

三个私有工程套件默认跳过，显式配置目录后才运行；配置不存在或不是目录时直接报错，不作为跳过处理：

| 环境变量 | 对应测试输入 |
|---|---|
| `RTL_VIEWER_ACCEPTANCE_CP7` | 原 CP7 Camera Link 验收副本根目录，通常位于 `tests/fixtures/cp7/project` |
| `RTL_VIEWER_ACCEPTANCE_P1` | 既有 P1 Vivado 验收工程根目录 |
| `RTL_VIEWER_ACCEPTANCE_P2` | 既有 P2 ISE 验收工程根目录 |

这些套件包含特定工程的结构断言，不适用于任意 HDL 文件夹。未运行私有套件不等于真实工程验收通过。

浏览器预览的文件服务默认关闭。下面将仓库样例复制到独立临时目录，允许在副本中编辑与保存；对话框会使用服务实际配置的目录，无需修改源码路径：

```powershell
$previewRoot = Join-Path '.tmp' ('browser-preview-' + [guid]::NewGuid().ToString('N'))
New-Item -ItemType Directory -Path $previewRoot -Force | Out-Null
Copy-Item -Path 'tests/samples/basic/*' -Destination $previewRoot -Recurse
$env:RTL_VIEWER_E2E_ROOT = (Resolve-Path $previewRoot).Path
npm run dev
# 打开 http://localhost:1420/?e2e ，点击“打开文件夹”。
# 停止服务后，可移除当前终端变量：Remove-Item Env:RTL_VIEWER_E2E_ROOT
```

文件访问限制在指定目录内；E2E mock 和文件服务不进入生产构建。真实工程编辑验收同样只使用隔离副本。

## 目录

```text
src/         前端：analysis/（按需运算语义与单模块逻辑）、parser/（HDL 解析）、model/（索引、层级树、搜索、导航历史、大纲、信号声明定位）、app/（编辑工作区、工程扫描、外部变更监视、信号链与模块元数据）、editor/（Monaco、标签页、代码补全）、ui/（树、搜索面板、大纲、状态栏、对话框、右键菜单、最近工程）
src-tauri/   本机 Rust 桌面后端：源码在 src/，负责文件扫描、编码读写与系统调用；另含桌面配置和图标
tests/       Vitest 测试；samples/ 为可提交样例，fixtures/ 为不入 Git 的私有验收副本；私有套件通过环境变量显式启用
scripts/     构建辅助（Build-Release.ps1、Invoke-Cargo.ps1、make-icon.mjs、Capture-Window.ps1 exe 窗口冒烟截图）
release/     便携 exe 交付物（Build-Release.ps1 生成，不入 Git）
```

`src/` 与 `src-tauri/` 属于同一个桌面应用，通过 `src/ipc.ts` 通信；HDL 解析和信号分析在前端执行，磁盘访问与编码读写在本机 Rust 后端执行。

| 生成目录 | 用途 |
|---|---|
| `dist/` | Vite 前端构建资源，打包时嵌入 exe |
| `src-tauri/target/` | Cargo 编译输出与增量缓存，清理后下次编译需重建 |
| `src-tauri/gen/` | Tauri 生成的配置 schema |
| `release/` | 正式便携交付物，只使用 `rtl-viewer.exe` |
| `.tmp/<task-slug>/` | 临时夹具、截图、日志与页面快照 |

上述生成目录不入 Git。`tests/fixtures/` 是真实工程验收副本，属于测试输入，不能作为普通构建缓存清理。
